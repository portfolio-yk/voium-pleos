# 소리 · 자동차 안의 실시간 화자 자막

Speechmatics 실시간 API로 마이크 음성을 받아 화자별 자막으로 보여 주는 인포테인먼트 UI 프로토타입입니다. **Node.js + 순수 JavaScript + HTML + CSS**로 작성했으며, 프레임워크·외부 패키지·빌드 단계가 없습니다.

## 실행

Node.js **22 이상**에서 프로젝트 폴더로 이동한 뒤 설정 파일을 만드세요.

```bash
cp .env.example .env
```

`.env` 파일에 [Speechmatics 포털](https://portal.speechmatics.com)에서 발급받은 API 키를 입력하고 저장합니다.

```env
SPEECHMATICS_API_KEY=발급받은_API_키
PORT=3000
```

```bash
npm start
```

[http://127.0.0.1:3000](http://127.0.0.1:3000)을 열고 왼쪽 위의 작은 **자막 시작** 버튼을 누른 뒤 마이크 권한을 허용하세요. 같은 버튼으로 종료할 수 있습니다. 외부 패키지가 없으므로 `npm install`은 필요하지 않습니다. 서버 종료는 터미널에서 `Ctrl+C`입니다.

API 키가 없으면 **미리보기** 표시와 함께 예시 자동차 대화를 자동으로 재생합니다. 미리보기는 실제 마이크 인식 결과가 아닙니다. 다음 주소로 동작을 지정할 수도 있습니다.

- [미리보기 강제 실행](http://127.0.0.1:3000/?mode=preview): API 키가 설정되어 있어도 예시 대화를 재생합니다.
- [실시간 모드](http://127.0.0.1:3000/?mode=live): 실제 마이크 연결 모드를 엽니다. API 키가 없으면 설정 안내가 표시됩니다.

`.env`를 수정했으면 서버를 다시 시작하세요. 포트가 사용 중이면 `.env`의 `PORT`를 변경하고 해당 포트로 접속합니다.

## 자막 화면

- 같은 사람이 말하는 동안 API가 여러 번 응답하더라도 하나의 문단으로 이어집니다.
- 다른 사람이 말하면 새 문단이 생기고 앞선 자막은 위로 이동합니다. 이전 화자가 다시 말하면 새로운 순서의 문단으로 표시합니다.
- 화자 번호와 일관된 색상으로 화자를 구분하고, 모든 발화의 글자 크기는 유지하고 현재 발화는 더 밝게, 지난 발화는 차분하게 표시합니다.
- 중간 인식 결과는 같은 위치에서 수정되고 확정 결과로 교체됩니다. 임시 화자 구분이 달라져도 확정되지 않은 문단을 기록으로 남기지 않습니다.
- 긴 대화는 최신 자막을 자동으로 따라갑니다. 사용자가 지난 대화로 스크롤하면 자동 이동을 멈추며 **최신 자막** 버튼으로 돌아올 수 있습니다.

메인 화면은 자막과 작은 시작·종료, 설정 버튼으로 구성합니다. 설정 화면, 화자 이름 편집, 내보내기 화면은 구현하지 않았습니다. 기존 `transcript.js`의 TXT/SRT 변환 함수는 코드에 유지합니다.

## 화자 색상과 읽기 흐름

현재 화자의 색상에 맞춰 화면 전체 배경이 짙은 블루·브라운·퍼플 등의 어두운 색으로 부드럽게 바뀝니다. 글자는 중립적인 밝은 색을 유지하며, 화자 번호와 이전 화자의 고정 색상도 유지합니다. 최신 문단에는 긴 색상 표식과 작은 **현재** 표시를 추가했습니다. **현재**는 마지막 자막을 뜻하며, 실제 음성 활동 감지(VAD) 표시는 아닙니다.

같은 화자의 단어가 추가될 때는 배경 전환을 반복하지 않습니다. 임시 자막의 화자가 바뀌면 180ms 동안 안정되는지 확인하고, 확정 화자는 바로 반영합니다. 알 수 없는 화자, 마이크 중지·오류, 지난 자막 탐색 중에는 중립 배경을 사용합니다. **최신 자막**으로 돌아오면 현재 화자 색을 다시 반영합니다.

배경 전환은 350ms이며 운영체제의 **동작 줄이기** 설정을 따릅니다. 깜빡임, 움직이는 파형, 글자 크기 변경은 추가하지 않았습니다. 배경별 자막과 화자 표시의 색 대비를 계산해 확인했습니다. 실제 차량 디스플레이와 환경광에서의 가독성은 별도 확인이 필요합니다.

## 설정 화면 연결

오른쪽 위 톱니바퀴 버튼은 `sori:open-settings`라는 취소 가능한 `CustomEvent`를 발생시킵니다. `detail`은 `{ path: '/settings' }`이며, 호스트가 이벤트를 처리하지 않으면 준비 중 안내를 표시합니다. `/settings` 페이지 자체는 구현하지 않았습니다.

차량 앱이나 별도 라우터에서 다음과 같이 연결할 수 있습니다. 이 코드는 호스트가 실제 설정 화면을 구현한 뒤 사용하세요.

```js
window.addEventListener('sori:open-settings', (event) => {
  event.preventDefault();
  // 호스트의 라우터 또는 네이티브 화면 전환 함수에 전달합니다.
  hostRouter.navigate(event.detail.path);
});
```

## 음성 인식과 API 키

마이크 입력을 AudioWorklet로 수집하고 PCM 오디오를 Speechmatics WebSocket으로 전송합니다. 한국어 실시간 중간·확정 자막과 `diarization: "speaker"` 화자 구분을 사용합니다. 브라우저의 마이크 권한이 필요하며, 로컬 주소는 마이크를 사용할 수 있는 보안 컨텍스트로 취급됩니다.

화자 번호는 목소리에 따른 세션 내 구분이며 실명이나 사람의 신원을 식별하지 않습니다. 중간 자막의 화자 정보는 확정 과정에서 달라질 수 있습니다. 동시에 말하거나 차량 소음이 크거나 발화가 짧으면 인식과 화자 구분에 오류가 생길 수 있습니다. 실제 인포테인먼트 단말 연동, 단말 해상도와 차량 마이크 품질은 검증하지 않았습니다.

일반 API 키는 서버의 `.env`에만 보관합니다. 서버가 유효기간 60초의 실시간 연결 토큰을 발급하고, 브라우저는 이 임시 토큰으로 Speechmatics에 직접 연결합니다. 토큰 유효기간은 새 연결을 시작할 수 있는 시간이며 기존 세션을 60초마다 끊는 설정이 아닙니다. 오디오는 이 Node 서버에 저장하지 않습니다. 실시간 API 사용 시 Speechmatics 계정의 요금 정책이 적용됩니다.

서버는 이 컴퓨터의 `127.0.0.1`에만 바인딩하고 허용된 공개 파일만 제공합니다. `.env`와 서버 소스는 웹으로 제공하지 않습니다. `.env`를 공유하거나 Git에 올리지 마세요.

## 파일과 검증

```text
server.js                  Node HTTP 서버, 정적 파일, 임시 토큰 발급
public/index.html          자막 화면 구조
public/styles.css          인포테인먼트 자막 스타일
public/app.js              화면 상태, 미리보기, 마이크 연결
public/conversation.js     연속 화자 문단과 교체 가능한 중간 자막
public/speaker-theme.js    화자 배경 테마와 임시 화자 변경 안정화
public/speechmatics.js     WebSocket과 마이크 수집
public/transcript.js       인식 결과 파싱과 TXT/SRT 변환 함수
public/audio-processor.js  AudioWorklet 오디오 처리
tests/                     Node 내장 테스트
.env.example               API 키 설정 예제
```

서버 코드를 수정할 때 자동으로 재시작하려면 `npm run dev`를 사용하세요. HTML/CSS/브라우저 JavaScript를 수정한 뒤에는 브라우저를 새로 고침합니다.

```bash
npm test
```

테스트는 파일 공개 범위, 요청 검증, 임시 토큰 발급 흐름, 음성 연결 수명 주기, 자막 파싱과 화자 문단 병합을 확인합니다. 실제 마이크와 Speechmatics 계정을 사용하는 실시간 인식은 자동 테스트에 포함하지 않습니다.

참고: [Speechmatics 실시간 API Quickstart](https://docs.speechmatics.com/speech-to-text/realtime/quickstart)
